## R-158-12 | quality | minor | declined

- **Finding**: Images and releases share one cap (PORTARR_SCANNER_MAX_IMAGES, 2000), releases are asked after the images.

- **Reason**: The cap is far above a homelab's images plus repositories; the docs now say the cap counts targets of both kinds.

## R-158-13 | security | medium | fixed

- **Finding**: The docs said the optional GitHub token lets the companion read a private repository; the code never sends it with the download, so an operator would hand it a credential it does not use.
- **Where**: trivy.md, ADR 0024, SPEC D-132, companions.md
- **Reason**: All now say the token only lifts the rate limit, should have no repository permission, and release scans are public repositories only.

## R-158-14 | security | low | fixed

- **Finding**: A private repository's name was sent to the companion although nothing readable could come back.
- **Where**: ReleaseTargets.cs
- **Reason**: A private repository is asked only through a mapping; a test covers it.

## R-158-15 | security | low | declined

- **Finding**: The download follows redirects after the first URL passes the github.com check.
- **Where**: scanner/release.ts
- **Reason**: GitHub serves release assets through its own CDN by redirect, the token is never sent with the download, and the file is size-capped while streaming; a manual redirect allow-list would pin the companion to GitHub's CDN naming.

## R-158-16 | architecture | major | fixed

- **Reason**: A repository whose address is not github.com is never asked; the docs and the ADR say so and name a host-qualified reference as the way to extend; a test covers it.
