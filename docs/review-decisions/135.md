# Review decisions — PR #135

Answers to the findings of the five review agents on the reworked code (Portarr is the master, adapters behind narrow contracts).

## R-135-1 | quality | minor | declined

- **Finding**: ReadBodyAsync allocates a body-sized array on every probe.
- **Where**: McpCheckRunner.ReadBodyAsync
- **Reason**: One probe per server every five minutes into a buffer capped by the checks' body limit: no measured cost and unchanged by this pull request.

## R-135-2 | quality | minor | fixed

- **Finding**: A health row is parsed twice and one corrupt row fails the whole load.
- **Where**: McpServerHealthStore.ReadAllAsync
- **Reason**: A row is read once; a row that cannot be read is skipped, so one bad row costs that server its history and not every server.

## R-135-3 | quality | minor | declined

- **Finding**: The attention decorator re-sorts the findings of the inner service.
- **Where**: McpAttentionService
- **Reason**: LINQ OrderBy is a stable sort: the order of the inner service is kept inside a level, which is all the decorator promises.

## R-135-4 | quality | minor | fixed

- **Finding**: The workstation page imports the stylesheet of the server page.
- **Where**: frontend/src/Mcp
- **Reason**: The shared classes are in McpDetail.module.css, imported by the three components that use them.

## R-135-5 | quality | minor | fixed

- **Finding**: A 5xx answer with a JSON-RPC body is reported healthy.
- **Where**: McpCheckRunner
- **Reason**: A server that answers with a 5xx is down whatever its body says, as the table of D-114 states; a test pins it.

## R-135-6 | spec | minor | fixed

- **Finding**: Every MCP tool is read-only, but the catalog write tools of D-86 exist.
- **Where**: SPEC D-112, mcp-servers.md
- **Reason**: The wording says the four tools of this vertical are read-only and that the catalog write tools refuse these sections.

## R-135-7 | spec | minor | fixed

- **Finding**: V5 and D-68 give different tool counts for the same slice.
- **Where**: docs/verticals/V5-ai-mcp.md
- **Reason**: V5 says seven at the first slice and eight today, like D-68.

## R-135-8 | test | minor | fixed

- **Finding**: The quote test passes when the renderer emits no command at all.
- **Where**: McpClientRendererContract
- **Reason**: It also asserts that the operator keeps an operation (the file entry) when a quote leaves the command out.

## R-135-9 | test | minor | fixed

- **Finding**: The variable test mutates a process-wide environment variable that no renderer reads.
- **Where**: McpClientRendererContract
- **Reason**: The mutation is gone; the test asserts that the client's own syntax names the variable, which is what a definition holds (D-111).

## R-135-10 | test | minor | declined

- **Finding**: The removal behaviour is checked in the contract, the golden files and a third test.
- **Where**: GoldenRenderingFixture
- **Reason**: They look at different layers: the contract at the adapter, the golden files at the composed output, the third at the sentence the operator reads.

## R-135-11 | test | minor | fixed

- **Finding**: The nine-ids test snapshots the wiring.
- **Where**: GoldenRenderingFixture
- **Reason**: Deleted: uniqueness is enforced at startup and tested in the registry fixture, and each client has a golden file and a contract fixture.

## R-135-12 | test | minor | fixed

- **Finding**: The contract fixtures parse the YAML again for every row.
- **Where**: McpClientRendererContract
- **Reason**: The servers are parsed once in a static field.

## R-135-13 | test | minor | declined

- **Finding**: The check runner has no redirect, oversized body or caller-cancellation case.
- **Where**: McpCheckRunnerFixture
- **Reason**: The runner uses the client of the HTTP checks, which follows no redirect by construction (D-50); the body cap is a read limit and a caller's cancellation is not turned into a timeout by the existing filter.

## R-135-14 | test | minor | fixed

- **Finding**: The e2e catalog fixture throws an unclear error when the section is missing.

## R-135-15 | test | minor | declined

- **Finding**: The e2e journey waits up to 30 s for the first probe.
- **Where**: tests/e2e/specs/mcp.spec.ts
- **Reason**: The wait ends at the first answer; the bound is the one the other health journeys use, and the stack is loaded once.

## R-135-16 | test | minor | fixed

- **Finding**: The golden update mode rewrites the file and then passes against itself.

## R-135-17 | security | low | fixed

- **Finding**: A comma in an argument is the array operator of PowerShell and would split it in two.
- **Where**: JsonConfigRenderer.Arg
- **Reason**: A comma is no longer plain: the argument is quoted. A test pins it on Windows.

## R-135-18 | architecture | minor | fixed

- **Finding**: Two rules for the default scope: one for the server page, one for the plan's removal.
- **Where**: McpRenderingService
- **Reason**: The rule is in one place, used by installation, removal and the all-clients rendering: the server's scope when the client holds it, else the client's first.

## R-135-19 | architecture | minor | declined

- **Finding**: The parser fixes the shape of every store (an address and a prefix).
- **Where**: CatalogParser.Mcp.cs
- **Reason**: The two stores need exactly that. A store with another shape (a region, a namespace) extends the secretStore section and the contract when it arrives; building it now would be guessing.

## R-135-20 | architecture | minor | fixed

- **Finding**: A wanted scope is checked against the closed list, not against the scopes of the clients named.
- **Where**: CatalogParser.Mcp.cs, IMcpVocabulary
- **Reason**: The vocabulary exposes each client's scopes and the catalog refuses a wanted scope a named client does not hold, naming the field.

- **Where**: Core, frontend, tests
