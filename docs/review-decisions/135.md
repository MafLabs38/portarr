# Review decisions — PR #135

Answers to the findings of the five review agents on the head commit of the first push (02b7fd1).

## R-135-1 | quality | major | fixed

- **Finding**: Accepting a capture silently drops a workstation whose edit kept conflicting.
- **Where**: McpCaptureService.AddToWorkstationsAsync
- **Reason**: The edit of one workstation is its own method; when every attempt conflicts the workstation is reported in the result's errors.

## R-135-2 | quality | major | fixed

- **Finding**: Dismissing the inbox needed only mcp.use while accepting needs catalog.write.
- **Where**: McpCapturesController.Dismiss
- **Reason**: Dismiss now requires catalog.write and a browser session, like accept.

## R-135-3 | quality | minor | fixed

- **Finding**: The workstation list and plan throw a 500 when the catalog changes between two reads.
- **Where**: McpWorkstationService
- **Reason**: One lookup by id; a server that vanished is skipped.

## R-135-4 | quality | minor | declined

- **Finding**: ReadBodyAsync allocates a buffer per probe and decodes the stream repeatedly.
- **Where**: McpCheckRunner
- **Reason**: One probe per server every five minutes, body capped at a few kilobytes: no measurable cost, and no reported symptom.

## R-135-5 | quality | minor | declined

- **Finding**: The %VERSION% placeholder is replaced in a JSON literal.
- **Where**: McpCheckRunner
- **Reason**: The version is Portarr's own constant, never an input; it cannot hold a quote.

## R-135-6 | quality | minor | declined

- **Finding**: _nextRuns is set before the probe and never rolled back.
- **Where**: McpHealthMonitor
- **Reason**: A cancelled tick delays a server by one interval; this is what the check scheduler does too, and the loop is single-threaded by construction.
