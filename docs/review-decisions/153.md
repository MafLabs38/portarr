# Review decisions: PR #153

Answers to the findings of the five review agents on the first head (ae61a31): R-153-1 to 16.

## R-153-1 | spec | major | fixed

- **Finding**: companions.md said companions are GET only except Backrest; the scanner is a second POST exception.
- **Where**: companions.md
- **Reason**: The sentence now names the scanner and says its POST asks for a report and changes nothing.

## R-153-2 | spec | major | fixed

- **Finding**: The writes allowed by D-16/D-31 and CLAUDE.md rule 6 did not list the request to the scanner.
- **Where**: SPEC.md D-31, CLAUDE.md
- **Reason**: D-31 is amended by D-131 and rule 6 names the request (a read-only pull of layers). CLAUDE.md is a contract file: the maintainer merges this PR.

## R-153-3 | spec | major | fixed

- **Finding**: The companion page said the scanner publishes no port while the compose example publishes one.
- **Where**: companions.md, server.ts
- **Reason**: Both say: publish the port only on an address Portarr reaches, the secret is the only gate.

## R-153-4 | spec | minor | fixed

- **Finding**: D-41 body, the connector status, V4 status line, F-SEC-01 rules, releasing.md and the README did not match the vertical.
- **Where**: SPEC.md, V4-maintenance.md, releasing.md, README.md
- **Reason**: All updated, including PORTARR_SCANNER_SECRET in the README.

## R-153-5 | security | medium | fixed

- **Finding**: The base images were pinned by tag only; the scanner reads every layer of every image.
- **Where**: scanner/Dockerfile, dependabot.yml
- **Reason**: Trivy and Node are pinned by version and digest, and Dependabot watches /scanner.

## R-153-6 | security | medium | declined

- **Finding**: The scanner image is built and pushed by CI but no step scans it.
- **Where**: ci.yml
- **Reason**: The portarr and agent images are not image-scanned either; scanning all three is a CI-wide chore after this PR. The repository scan already covers the Dockerfile.

## R-153-7 | security | low | fixed

- **Finding**: The container root filesystem was writable.
- **Where**: docker-compose.yml
- **Reason**: read_only with a tmpfs for /tmp; tested with a real scan.

## R-153-8 | security | low | declined

- **Finding**: A reference may name a private registry host (SSRF).
- **Where**: reference.ts, trivy.ts
- **Reason**: Only the holder of the shared secret can ask, and the staging machine's firewall drops traffic to the local network.

## R-153-9 | security | low | fixed

- **Finding**: The scanner tracked references without a global cap, and a comment said no port is published.
- **Where**: scanner.ts, server.ts
- **Reason**: A cap of 2000 references (PORTARR_SCANNER_MAX_IMAGES) and a correct comment.

## R-153-10 | architecture | minor | fixed

- **Finding**: The deployment story contradicted itself, the digest kept its own copy of the attention rule and two threshold values did nothing.
- **Where**: companions.md, ADR 0023, FleetDigest.cs, PortarrOptions.cs
- **Reason**: Docs aligned; the digest reuses the Core rule and honours the threshold; the threshold is critical or high only.

## R-153-11 | architecture | minor | declined

- **Finding**: The provider is named after Trivy but speaks the scanner's own protocol.
- **Where**: Portarr.Providers.Trivy
- **Reason**: The companion is the Trivy command line; renaming a project for a seam that has one implementation can wait for a second one.

## R-153-12 | architecture | minor | declined

- **Finding**: A floating or rebuilt tag is scanned as the registry serves it now, not as it runs.
- **Where**: ImageReference.ScanReference
- **Reason**: Documented limitation; pinning the scan to the running digest is the next step and would change how results are keyed.

## R-153-13 | quality | minor | fixed

- **Finding**: A failed scan request skipped the read, free text became a reason code and the report was normalised twice.
- **Where**: MaintenanceMonitor.cs, ImageVulnerabilities.cs
- **Reason**: The read always happens, reasons are a closed set, one normalisation.

## R-153-14 | quality | minor | declined

- **Finding**: Silent drop of non-plain references, a dense freshness condition and growing positional parameters.
- **Where**: TrivyImageScanner.cs, MaintenanceMonitor.cs, MaintenanceService.cs
- **Reason**: Readability only; the drop is a safety rule and the parameters follow the existing style of the report.

## R-153-15 | test | minor | fixed

- **Finding**: No test for a failed scan request while the read works.
- **Where**: MaintenanceScannerFixture.cs
- **Reason**: Test added.

## R-153-16 | test | minor | declined

- **Finding**: No Playwright spec, no scanner coverage figure, and several tests to remove, merge or add cases to.
- **Where**: tests/e2e, ci.yml, ImageVulnerabilitiesFixture.cs
